# go-solid-refactoring

Учебный проект: рефакторинг системы управления заказами по принципам SOLID.
Исходная реализация сохраняла заказ в SQLite и одновременно отправляла
email-уведомление внутри одного метода, что жёстко связывало бизнес-логику
с конкретной БД и конкретным каналом уведомлений. После рефакторинга
`OrderService` зависит только от интерфейсов `RepositoryWriter` и `Notifier`
и не знает ни о SQLite, ни о способе доставки уведомления.

## Как устранены жёсткие связи (соответствие принципам SOLID)

| Принцип | Как реализован в решении |
|---|---|
| **S** — Single Responsibility | `SQLiteRepo` отвечает только за работу с БД (инициализация схемы и сохранение заказа), `EmailSender`/`SMSSender` — только за отправку уведомления, `OrderService` — только за бизнес-логику создания заказа |
| **O** — Open/Closed | `OrderService` не меняется при добавлении новых баз данных или каналов уведомлений — достаточно реализовать существующий интерфейс новой структурой (`SMSSender` добавлен без единой правки в `OrderService`) |
| **L** — Liskov Substitution | `EmailSender` и `SMSSender` реализуют единый контракт `Notifier.Send(customer, message string) error` и взаимозаменяемы — `OrderService` работает с любым из них без проверок конкретного типа |
| **I** — Interface Segregation | Инициализация БД (`RepositoryInitializer.Init()`) вынесена отдельно от записи (`RepositoryWriter.SaveOrder()`), чтобы клиенты, которым инициализация не нужна (например, тестовый мок), не были обязаны её реализовывать |
| **D** — Dependency Inversion | `OrderService` получает `RepositoryWriter` и `Notifier` через конструктор `NewOrderService(repo, notifier)`, а не создаёт конкретные реализации внутри себя |

Дополнительно в `main` продемонстрирована работа одного и того же
`OrderService` с двумя разными реализациями `Notifier` (email и SMS) без
изменения кода сервиса.

## Тесты

В `main_test.go` `OrderService` тестируется полностью на моках
(`MockWriter`, `MockNotifier`), без обращения к реальной БД и реальной
отправке сообщений. Проверяются:

- содержимое сохранённого `Order` целиком (`Customer`, `Products`, `Total`, `Status`) и текст отправленного сообщения;
- поведение при ошибке `RepositoryWriter`: ошибка возвращается вызывающему коду, `Notifier.Send` не вызывается;
- поведение при ошибке `Notifier`: запись в репозиторий уже произошла, а вызывающий код получает ошибку отправки.

## Запуск

```bash
go run main.go
```

Ожидаемый вывод:

```
[Email] Уведомление отправлено клиенту Иван: Ваш заказ на сумму 10.50 принят в обработку
[SMS] Уведомление отправлено клиенту Мария: Ваш заказ на сумму 5.00 принят в обработку
```

Запуск тестов:

```bash
go test ./...
```
